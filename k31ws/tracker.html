Gap analysis

A warm D3-32 step bench takes 247 s wall for ~40 s of cases: container+imports 8 s, config 11 s, dist init 10 s, model+dummy load 23 s, KV profile run 42 s, KV prepare + CuTe compiles 21 s, JIT kernel warmup 10 s, prefill-glue + tokenspeed MLA Triton compiles 39 s, router/CuTe warmup 5 s, serving-shape warmup 18 s, cases 28 s (incl. late Triton JITs), teardown 13 s. Root cause of most JIT time: the container /tmp (TRITON_CACHE_DIR, CUDA_CACHE_PATH) is a fresh tmpfs per srun step, so every run recompiled every Triton kernel; fixed (Lustre caches), effect being measured. Cold builds on new sources: flashkda_split 80-135 s, dcp_exchange 34 s (was rebuilt per overlay; now shared by digest). Kimi K3 CuTe cache misses 26-45 kernels/rank on a warm overlay (key includes real tensor addresses): ~27 s per start. NVFP4 slices: model init 235-291 s + MegaMoE runtime setup up to 154 s, not yet attributed. Queue: 80% of hold-GPU-minutes lock-busy but 32% of that in failed runs; holds are backfill jobs preempted 30-60 min after start (PreemptMode CANCEL), so the pool is 2-3 nodes for 14 agents and waits are 5-47 min for 4-GPU requests.

Current inefficiencies

  • dcp_exchange torch extension rebuilt 34 s per new overlay although digest-named (fixed: shared build root)
  • CuTe cache keys include real tensor addresses: ~26-45 kernels/rank recompiled every start, ~27 s (owner: kernels traced with real buffers)

  • 30 s polling + greedy first-come lock grabbing: handoff gaps, whole-node starvation, no fairness across agents (fixed: wsplan.py)
  • 32% of busy GPU-minutes in runs exiting non-zero (preemption kills + agent bugs that a CPU-side import/config check would catch)
